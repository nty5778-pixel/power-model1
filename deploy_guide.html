    서버 띄우기

    Render · 약 15분 (빌드 대기 포함)

    여기가 실제로 모델이 도는 곳입니다. 매일 아침 “내일 DA로 살까 RT로 살까”를 계산해서 답을 돌려줍니다.

    설정이 자동으로 잡히지 않습니다 — 직접 넣으셔야 합니다

    저장소에 설정 파일이 있지만, New → Web Service로 만들면 Render가 그 파일을 읽지 않습니다. 아래 값을 화면에 직접 입력해 주세요.

    1. Render에서 New → Web Service를 누르고 저장소를 고릅니다.
    2. 아래 두 칸을 채웁니다.
    Build Command
    pip install -r requirements.txt
    Start Command
    uvicorn app:app --host 0.0.0.0 --port $PORT --timeout-keep-alive 120
    1. 나머지 — Language Python 3 · Branch main · Health Check Path /health · Instance Type Free · 서비스 이름 powermodel1
      이름이 달라지면 주소가 바뀌어서 워크플로 파일도 고쳐야 합니다.
    2. 환경변수 4개를 넣습니다.
    이름값왜
    API_KEY아무 긴 임의 문자열 4단계에서 똑같은 값을 씁니다. 복사해 두세요
    DATA_DIR/opt/render/project/src/data 없으면 학습 데이터를 못 찾습니다
    PYTHON_VERSION3.11
    OMP_NUM_THREADS1 Free는 CPU가 작아서, 이걸 넣어야 오히려 빨라집니다
    1. 배포가 끝나면 https://powermodel1.onrender.com/health 를 열어봅니다.
      처음 열 때 1~3분 걸릴 수 있습니다. 정상입니다.

    Free 플랜은 15분 쉬면 잠듭니다 — 대비해 뒀습니다

    잠든 뒤 첫 요청은 서버가 깨어날 때까지 1~3분 기다립니다. 그래서 4단계 자동 실행에 “서버 먼저 깨우기” 단계를 넣고, 실행 시각도 20분 앞당겨 뒀습니다. 입찰 마감(10시)에는 영향이 없습니다.

    메모리는 실측 188MB로 한도 512MB 안에 넉넉히 들어갑니다. 나중에 더 빠른 응답이 필요해지면 Starter($7/월)로 바꾸기만 하면 되고, 자동 실행은 그대로 두셔도 됩니다.

    선택 — 넣지 않으면 기본값으로 돕니다

    ALLOC_MODE(기본 m1_only)와 M1_DA_THRESHOLD(기본 0.5)는 매수 판단 규칙 자체입니다. 검증을 거쳐 정한 값이라 손대실 이유가 없습니다. 바꾸시려면 반드시 백테스트로 먼저 확인하세요.

    ✓ 이렇게 되면 성공 — 브라우저에 {"ok":true, ...} 가 보인다.

    매일 자동 실행 연결하기

    n8n · 약 20분

    n8n이 매일 정해진 시각에 ERCOT 예보와 날씨를 모아 서버에 보내고, 답을 받아 시트에 적습니다. 다음 날에는 실제 가격을 채워 채점합니다.

    1. 워크플로 파일 2개를 불러옵니다 — n8n_1_daily_predict.json, n8n_2_backfill_lookback.json.
    2. ERCOT 비밀번호를 넣습니다. 두 워크플로 각각에서 ERCOT Token 노드를 열고, Body Parameters의 password 칸에 있는 CHANGE-ME-ERCOT-PW를 실제 비밀번호로 바꿉니다.
      두 파일 모두 해야 합니다.
    3. Credential 4개를 만듭니다. 이름을 아래와 정확히 같게 만들면 자동으로 연결됩니다.
    Credential 이름종류넣을 값
    ERCOT Subscription KeyHeader Auth Name Ocp-Apim-Subscription-Key
    Value = ERCOT 구독키
    Render Model APIHeader Auth Name x-api-key
    Value = 3단계 API_KEY와 똑같은 값
    Anthropic APIHeader Auth Name x-api-key
    Value = Claude API 키
    (이름 자유)Google Sheets OAuth2 또는 서비스 계정 — 시트 노드 6곳에 지정

    ERCOT 비밀번호는 워크플로 안에 저장됩니다

    ERCOT은 아이디·비밀번호로 이용권을 받는 방식이라 요청 내용에 직접 들어가야 하고, n8n의 비밀 보관함(Credential)으로는 뺄 수가 없습니다. 워크플로를 외부로 내보내거나 공유하지 마세요.

    서비스 계정으로 시트에 연결하시는 경우, 1단계 스프레드시트를 그 계정 이메일에 편집 권한으로 공유해야 합니다.

    실행 시각 — 이미 설정돼 있습니다. 확인만 하세요.

    하는 일현지 시각왜 그때인가
    내일 배분 계산여름 07:40 / 겨울 06:40 CT DA 입찰 마감 10시 전에 답이 나와야 합니다. 서버 깨우는 시간 20분 포함
    어제 실적 채우기여름 11:00 / 겨울 10:00 CT정산이 확정된 뒤
    주간 성적 정리월요일그날 실적을 채운 40분 뒤

    맨 앞에 “서버 깨우기” 단계가 들어 있습니다

    Free 플랜은 15분 쉬면 잠들기 때문에, 본 작업 전에 서버를 먼저 깨웁니다. 이 단계가 몇 분씩 걸리는 건 정상입니다 — 실패가 아니라 기다리는 중입니다.

    실적을 채우는 두 번째 작업에는 깨우기가 없습니다. 그 작업은 서버를 쓰지 않고 ERCOT 정산가와 시트만 다루기 때문입니다.

    ✓ 이렇게 되면 성공 — 워크플로 2개가 보이고, 빨간 경고 표시가 없다.

    첫 실행 확인하기

    가장 중요한 단계 · 약 10분

    여기서 눈으로 3가지만 확인하면 조용히 잘못 도는 경우를 거의 다 잡을 수 있습니다. 자동으로 돌기 시작하면 아무도 안 보게 되니 지금 확인하세요.

    1. n8n에서 첫 번째 워크플로를 수동으로 한 번 실행합니다.
    2. predictions 시트에 4줄(내일부터 나흘치)이 생겼는지 봅니다.
    3. 그 4줄에서 아래 3칸을 확인합니다.
    확인할 칸정상비어 있거나 이상하면
    alloc_modem1_only 시트 제목 철자가 틀렸습니다 → 1단계
    WX_t_anom_F숫자 (예 1.6) 날씨가 안 넘어왔습니다 → 워크플로 확인
    DA_fraction0 또는 1 아래 설명 참조

    DA 비중이 0이나 1로만 나오는 건 정상입니다

    지금 규칙은 “평소엔 RT, 신호가 뜬 날만 전량 DA”입니다. 다만 이상기온인 날에는 중간값이 나옵니다 — 이때는 같은 줄 WX_overlay 칸에 hot+9F 같은 표시가 있습니다. 지난 531일 기준 20일에 한 번꼴(4.1%)입니다.

    WX_overlay가 비어 있는데 중간값이면 규칙 설정이 잘못된 것입니다.

    실제로 매수하실 때

    DA_MW가 36.7처럼 소수로 나옵니다. MW 단위로 반올림해서 집행하시면 되고, 1MW 미만이면 그냥 전량 RT로 하세요. 이 정도 차이는 성과에 영향이 없습니다.

    1. 다음 날 두 번째 워크플로를 수동 실행해 DA_actual이 채워지는지 봅니다.
    2. 기록이 20일 넘게 쌓이면 주간 성적이 lookback 시트에 자동으로 남습니다.
    ✓ 이렇게 되면 성공 — 시트에 4줄이 쌓였고, 위 3칸이 모두 정상이다.
